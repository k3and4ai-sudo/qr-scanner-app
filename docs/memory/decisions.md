## ADR-001: ローカル HTTPS 化に `@vitejs/plugin-basic-ssl` を採用

- **日付**: 2026-10-14
- **背景**: Android 実機等のモバイルブラウザからカメラ機能（`navigator.mediaDevices.getUserMedia`）を利用するには、セキュリティ要件として HTTPS 通信が必須。
- **決定**: Vite 公式推奨の `@vitejs/plugin-basic-ssl` を導入し、ポート 3000 で自己署名証明書付き HTTPS サーバーとして稼働。
- **結果**: 同一 Wi-Fi 上の Android 実機から `https://192.168.0.10:3000/` で安全にカメラアクセスとデバッグが可能になった。

## ADR-002: ネイティブ BarcodeDetector と jsQR のハイブリッドQRデコード方式

- **日付**: 2026-10-14
- **背景**: モバイル端末のカメラや高解像度写真ファイルから高精度かつ高速にQRコードを読み取る必要があった。
- **決定**: 
  1. ネイティブのハードウェアアクセラレーションが効く `BarcodeDetector API` を最優先で試行。
  2. 未対応ブラウザや検出不能画像に対しては、大津の二値化（適応的閾値処理）およびマルチ解像度スケーリングを施した `jsQR` でフォールバック。
- **結果**: 暗所、ピンボケ、高解像度のスクリーンショットでも業界トップクラスの認識精度を実現。

## ADR-003: LINE 公式 QR コード判定と専用起動ボタンの新設

- **日付**: 2026-10-14
- **背景**: LINE の友だち追加 QR コードや公式アカウントリンクをスキャンした際、安全スコアの誤判定やブラウザ遷移による不便が生じていた。
- **決定**:
  1. `line.me`, `page.line.me`, `line://` を公式安全ドメインとしてスコア 100 点判定。
  2. 結果カードに LINE カラーの「📱 LINEで開く」専用ボタンを配置し、端末内の LINE アプリを直接起動。
- **結果**: ユーザーが直感的に友だち追加を行えるシームレスな体験を実現。

## ADR-004: ナビゲーションの二段表示レイアウトへの刷新

- **日付**: 2026-10-14
- **背景**: 機能追加（ファイル読み込み）に伴い、スマートフォンの1行タブでは横幅が圧迫され押しにくくなった。
- **決定**:
  - **上段（メイン読取系 2列）**: `📷 QRスキャナー` / `📁 ファイル読み込み`
  - **下段（サブ機能系 3列）**: `✨ QR作成` / `🕒 履歴` / `📖 取説`
- **結果**: 親指での操作性が大幅に向上し、機能の重要度に応じた分かりやすいUIとなった。

## ADR-005: PWA 機能強化（オフライン Service Worker & インストールUI）

- **日付**: 2026-10-15
- **背景**: オフライン環境（地下や電波の途切れた場所）での起動、および Android/iOS ホーム画面への追加体験を最適化する必要があった。
- **決定**:
  1. 高解像度 PNG アイコン（192x192, 512x512, maskable）を作成し `manifest.json` に完全準拠。
  2. `public/sw.js` による Stale-While-Revalidate キャッシュ戦略を導入し、アプリシェルと静的アセットをオフライン保持。
  3. `beforeinstallprompt` イベントをフックする `usePwaInstall` と、ヘッダーの「📲 ホーム画面に追加 / PWA起動中」バッジを新設。
- **結果**: 完全オフライン下でもアプリが即座に起動可能となり、ワンタップでホーム画面へインストールできるネイティブアプリ級の体験を実現。

## ADR-006: PWA 新バージョン検知トーストバナーの導入

- **日付**: 2026-10-15
- **背景**: サーバー側の更新後、次回のキャッシュ切り替えを待つだけでなく、ユーザーがワンタップで即座に最新版を適用できるようにしたかった。
- **決定**:
  1. `public/sw.js` に `SKIP_WAITING` メッセージ受信リスナーを追加し、キャッシュバージョンを更新。
  2. `src/registerServiceWorker.js` で `onupdatefound` および `registration.waiting` を検知するコールバック `onUpdate` を新設。
  3. `src/components/UpdateNotificationToast.jsx` を作成し、新バージョン検出時に画面下部へ「🔔 新バージョンがあります [今すぐ更新]」トーストを表示。
- **結果**: スマホゲーム等のネイティブアプリ同様、ワンタップで瞬時に最新機能へとリロード更新できる優れたUXを実現。

## ADR-007: スキャン履歴メタデータ拡張・ゴミ箱機能 ＆ QR作成解説モーダルの新設

- **日付**: 2026-10-15
- **背景**:
  1. スキャン履歴で「後から見返したときに何のスキャンか判別し、メモを残したい」「誤削除を防ぐゴミ箱が欲しい」という要望があった。
  2. QR作成のテンプレート（Wi-Fi、vCard名刺）で、「各パラメータ（WIFI:, T:, S:, P: や N:, TEL:, EMAIL: 等）の意味や正しい書き方が分からない」という課題があった。
- **決定**:
  1. `src/utils/storage.js` を拡張し、タイトル・コメント・秒単位の完全日時（`YYYY/MM/DD HH:mm:ss`）・安全スコア・ゴミ箱フラグ（`isTrash`）をデータモデルに統合。
  2. `src/components/ScanHistory.jsx` に「履歴一覧」と「ゴミ箱」のサブタブ、インラインタイトル・コメント編集機能、復元・完全削除機能を実装。
  3. `src/components/TemplateGuideModal.jsx` を新設し、Wi-Fi と vCard の全キーワードの意味解説、およびフォーム入力からワンクリックでQR文字列を自動生成して反映する入力支援を搭載。
  4. `public/sw.js` の `install` 完了時に `skipWaiting()` を自動実行し、アプリ再起動時に確実に最新版がアクティブ化されるよう最適化（v3）。
- **結果**: スキャン記録の管理性が大幅に向上し、不慣れなユーザーでも迷わず高度なWi-Fiや名刺QRコードを作成できるようになった。

## ADR-008: スキャン履歴エクスポート機能（CSV / JSON）および安全スコア非100点時のURL遷移警告確認の導入
- **日付**: 2026-10-15
- **ステータス**: 承認・実装完了
- **背景**:
  1. スキャン履歴（タイトル・コメント・秒単位日時・安全スコア・URL）を外部ツール（Excelやスプレッドシート、他システム）へ出力したい要望。
  2. 潜在的なリスク（HTTP非暗号化通信、短縮URL、不審TLD、クエリパラメータ等）を持つURLへ不用意にアクセスしてしまう事故を防ぐため、安全スコアが完全満点（100点）以外のすべてのURL遷移時にユーザー確認を必須化。
- **決定内容**:
  1. `src/utils/exportHistory.js` を新設し、UTF-8 BOM付きCSV（Excel文字化け防止）および整形JSONのダウンロード機能を実装。
  2. `src/components/ScanHistory.jsx` に「CSV出力」「JSON出力」ボタンを設置。
  3. `src/utils/urlSafety.js` を改定し、スコア100点のみを完全安全（safe）と位置づけ、100点未満（60〜99点）は要確認（warning）として明示。
  4. `src/components/ResultCard.jsx` および `src/components/ScanHistory.jsx` において、安全スコアが100点満点以外のURLを開く際は直前の確認モーダル（スコア数値、検出理由、Safe Browsing事前照会、アクセス強行、キャンセル）を割り込ませて表示。
  5. `public/sw.js` のキャッシュバージョンを `v4` に更新。

## ADR-009: 取扱説明書（HTML / PDF / Markdown）への画面キャプチャ網羅的挿入と自動生成パイプラインの構築

- **日付**: 2026-10-15
- **ステータス**: 承認・実装完了
- **背景**:
  ユーザーが取扱説明書（Web画面、HTML単体版、PDF印刷版）を読んだ際に、文字だけでなく実際のアプリ画面とボタン配置・操作結果が直感的に一目でわかるよう、画面キャプチャを豊富に挿入することが求められた。
- **決定内容**:
  1. ヘッドレス Google Chrome を用いて、主要画面のモバイル比率高精細キャプチャ全6枚を撮影（`01_qr_scanner_main.png`, `02_qr_scanner_result.png`, `03_file_scanner.png`, `04_qr_generator.png`, `05_scan_history.png`, `06_user_manual.png`）。
  2. `USER_MANUAL.md` の各セクション（各ボタン対応箇所）直下に画像とキャプションを挿入。
  3. `scripts/generate_manual_html_and_pdf.py` を作成し、画像を Base64（`data:image/png;base64,...`）に変換してインライン埋め込みしたスタンドアロン `USER_MANUAL.html` を生成。
  4. ヘッドレス Chrome の `--print-to-pdf` により、A4サイズ全14ページの高品質な `USER_MANUAL.pdf` を自動レンダリング。
  5. `public/` および `dist/` に同期し、GitHub Pages およびローカル環境のどこからでも閲覧・ダウンロード可能に設定。
- **結果**:
  - HTMLファイルやPDFファイルを単体で移動・ダウンロード・配布しても、画像抜けやリンク切れが一切発生しない堅牢な構成となった。
  - アプリ起動時の「QRスキャナー (上段左)」から「QRスキャナーを起動」を押し、スキャン完了後に「URLを開く (水色ボタン)」を押すまでの基本フローや、履歴・QR作成・ファイル読み込みの画面イメージが極めてわかりやすく視覚化された。
