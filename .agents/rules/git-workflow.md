# 専用ブランチと変更管理規約 (Git Workflow Rules)

本規約は、Claude Code Projects の「専用ブランチとPR管理」の概念を Antigravity 上で実践・標準化するための指針です。

## 1. 専用トピックブランチの作成規則

新機能の実装や不具合修正を行う場合、原則として `main` ブランチで直接開発を行わず、専用のトピックブランチを作成して作業します。

- **新機能追加**: `feature/<機能名>` (例: `feature/export-csv`, `feature/pwa-support`)
- **不具合修正**: `fix/<問題名>` (例: `fix/camera-selection`, `fix/sound-toggle`)
- **ドキュメント整備**: `docs/<内容>` (例: `docs/project-guide`)
- **リファクタリング**: `refactor/<対象>` (例: `refactor/decoder-logic`)

## 2. ビルド・検証ゲート (必須要件)

ブランチをマージする前に、以下の検査を必ずパスさせること：

1. **静的ビルド検証**:
   ```bash
   npm run build
   ```
   ビルドエラーおよび警告が存在しないことを確認。
2. **動作確認**:
   ローカル開発環境（`https://localhost:3000` または実機）での基本動作に退行（リグレッション）がないことを確認。

## 3. コミットメッセージ規約 (Conventional Commits)

コミットメッセージは以下の接頭辞を使用し、変更理由が分かる簡潔な日本語または英語で記述すること：

- `feat:` 新機能の追加
- `fix:` バグの修正
- `docs:` ドキュメントのみの変更
- `style:` コードの意味に影響を与えない書式・フォーマットの変更
- `refactor:` バグ修正や機能追加を含まないコードの再構築
- `test:` テストの追加・修正
- `chore:` ビルド設定や補助ツールの更新

## 4. マージとクリーンアップ

- 変更と検証が完了したら、`main` ブランチに切り替えてトピックブランチの内容をマージします。
- 作業完了後のトピックブランチは削除し、リポジトリを常にクリーンな状態に保ちます。
