# 進捗管理とドキュメンテーション指針 (Progress Management Rules)

本プロジェクト（QRコードスキャナーアプリ）では、開発セッションの継続性と品質向上のため、以下の進捗管理ルールを常時適用します。

## 1. 進捗報告書の作成タイミング
- ユーザーから「進捗報告」「午前進捗報告」「本日最終進捗報告」「今日のまとめ」「作業終了」「再開メモ」などの依頼があった際は、即座に [`progress-reporting`](file:///media/k3and4/For_AI_Data/Antigravity/TestApp/qr-scanner-app/.agents/skills/progress-reporting/SKILL.md) スキルに従って報告書を作成すること。
- キリの良いフェーズ完了時や作業終了の気配がある場合、進捗報告の作成をユーザーに能動的に提案すること。

## 2. 報告書の配置場所と命名規則
- 保存先ディレクトリ: `docs/reports/`
- ファイル命名規則:
  - 午前セッション終了時: `YYYY-MM-DD_午前進捗報告.md`
  - 日次作業終了時: `YYYY-MM-DD_本日最終進捗報告.md`
  - 都度進捗: `YYYY-MM-DD_進捗報告.md`

## 3. ドキュメント品質ガイドライン
- **Obsidian / Markdown 互換**:
  - 見出し構造（`##`, `###`）を明確にし、リストや表を適切に使用する。
  - 必要に応じて Mermaid ダイアグラムや Alert（`> [!NOTE]`, `> [!TIP]` など）を活用する。
- **次回再開手順の必須化**:
  - 次回のセッション開始時に誰でもすぐ復帰できるよう、「再開時の確認手順」「次回着手予定タスク」を必ず記載すること。
- **ファイルリンクの付与**:
  - 変更したファイルや重要ファイルへのリンク（`[filename](file:///path/to/file)`）を必ず記載すること。

## 4. バージョン管理 (Git) との連動
- 進捗報告書を作成・更新した後は、Git ステータスを確認し、変更内容をコミット（例: `git commit -m "docs: add progress report for YYYY-MM-DD"`）してリポジトリの整合性を保つこと。
