# 進捗管理 & レポート生成スキル (progress-reporting)

本スキルは、`Nursing_facility` プロジェクトで確立された実践的かつ再開しやすい進捗管理フローに基づき、
`docs/reports/` 配下に標準化された進捗報告マークダウンを作成・更新するための手順書です。

## 目的
1. **作業内容の客観的記録**: 実装内容、変更ファイル、テスト・検証結果の明文化。
2. **スムーズな次回再開**: 復帰時に迷わず作業再開できる「再開コマンド」「確認事項」「残タスク」の記録。
3. **Obsidian / GitHub 互換**: Mermaid図、Markdownテーブル、Alert（`> [!NOTE]` 等）を活用した見やすいドキュメント化。
4. **Git 連動**: 作成した報告書をバージョン管理に安全に記録。

---

## 実行手順

### 1. 直前の作業内容とGit差分の確認
以下のコマンド等で、直近の作業差分や変更ファイルを確認します。
- `git status -s`
- `git log -n 5 --oneline`
- `git diff --stat`

### 2. 報告書ファイルの決定
報告先ディレクトリは **`docs/reports/`** とします。
ファイル名ルール：
- 午前セッション終了時: `docs/reports/YYYY-MM-DD_午前進捗報告.md`
- 1日の作業終了時: `docs/reports/YYYY-MM-DD_本日最終進捗報告.md`
- 都度の進捗まとめ: `docs/reports/YYYY-MM-DD_進捗報告.md`

### 3. レポートフォーマットに従った生成
以下のテンプレート構成に沿って Markdown を記述します。

```markdown
# YYYY-MM-DD [午前進捗報告 & 再開準備メモ / 本日最終進捗報告]

## 1. 本日の作業概要（ハイライト）
- 達成した主要項目を箇条書きで簡潔に記載。

---

## 2. 実施・完了した作業詳細
### ① [機能名 / 変更テーマ]
- **実装内容**: 何を変更したか。ファイルへのリンク（例: [App.jsx](file:///path/to/src/App.jsx)）を含める。
- **検証結果**: ローカル動作確認、UI表示、単体テスト等の結果。

---

## 3. 現在の稼働・設定状況
- **開発サーバー**: `npm run dev`（ポート `http://localhost:5173` 等）
- **主要な設定・環境**: 使用ライブラリ、ブラウザ要件、HTTPS/カメラ権限の状況など

---

## 4. 次回再開手順 & 予定タスク

### 再開時の確認手順
1. 開発サーバーの起動確認（`npm run dev`）。
2. ブラウザでのアクセス確認。

### 次回の作業予定テーマ
1. [優先度高のタスク]
2. [UI/機能ブラッシュアップ]

---
本日もお疲れ様でした！次回スムーズに再開できるよう準備を整えております。
```

### 4. Git コミットの実行
作成後、ユーザーに報告書へのリンクを案内し、必要に応じて Git コミットを行います。
```bash
git add docs/reports/
git commit -m "docs: add progress report for YYYY-MM-DD"
```
